# Спецификация формата QTIVP, версия 1

**Статус:** открытый формат. Настоящая спецификация передана в общественное
достояние (CC0). Любой может реализовать формат QTIVP в своём ПО — бесплатно,
без лицензионных отчислений и без разрешения авторов.

- Расширение файла: `.qtivp`
- MIME-тип: `application/x-qtivp`
- Контрольная сумма: CRC-32/ISO-HDLC (zlib-совместимая)
- Порядок байтов: little-endian, если не указано иное

## 1. Назначение

QTIVP — контейнер для хранения **нескольких фотографий в одном файле**.
Фотографии хранятся в исходном виде (например, JPEG-файл кладётся в альбом
байт в байт, без перекодирования и потери качества). Каждая запись имеет
метаданные: имя, MIME-тип и размеры.

## 2. Структура файла

```
+----------------------+
|       Заголовок      |  16 байт
+----------------------+
|   Индекс записей     |  count × (запись переменной длины)
+----------------------+
|   Данные (blob'ы)    |  смещения и размеры — из индекса
+----------------------+
```

## 3. Заголовок (16 байт)

| Смещение | Размер | Поле     | Значение |
|---------:|-------:|----------|----------|
| 0        | 8      | magic    | ASCII `QTIVP1\0\0` (байты `51 54 49 56 50 31 00 00`) |
| 8        | 2      | version  | `uint16` LE, = 1 |
| 10       | 2      | flags    | `uint16` LE, зарезервировано, = 0 |
| 12       | 4      | count    | `uint32` LE — количество записей |

## 4. Индекс (записи подряд, сразу после заголовка)

Каждая запись:

| Размер | Поле       | Описание |
|-------:|------------|----------|
| 2      | nameLen    | `uint16` LE — длина имени в байтах |
| var    | name       | имя файла в UTF-8 (например `sunset.jpg`) |
| 2      | mimeLen    | `uint16` LE — длина MIME-типа в байтах |
| var    | mime       | MIME-тип в ASCII (например `image/jpeg`) |
| 4      | width      | `uint32` LE — ширина в пикселях, 0 = неизвестно |
| 4      | height     | `uint32` LE — высота в пикселях, 0 = неизвестно |
| 4      | rawSize    | `uint32` LE — размер **несжатого** blob'а в байтах |
| 4      | storedSize | `uint32` LE — размер blob'а как он хранится (сжатый или нет) |
| 8      | offset     | `uint64` LE — абсолютное смещение blob'а от начала файла |
| 4      | flags      | `uint32` LE: бит 0 (`0x1`) = blob сжат zlib, остальные = 0 |
| 4      | crc32      | `uint32` LE — CRC-32 **несжатого** blob'а |

Фиксированная часть записи — 32 байта (после name и mime). Blob'ы начинаются
сразу после последней записи индекса; записи могут идти в любом порядке,
offset указывает точное положение.

## 5. Данные

Blob — исходные байты файла изображения (JPEG/PNG/WebP/AVIF/…). Формат данных
определяется полем `mime` записи; сам контейнер не требует конкретного
формата изображения.

### 5.1 Сжатие zlib

Если установлен флаг `0x1`, blob хранится сжатым:

```
stored = [uint32 BE: rawSize][zlib-поток RFC 1950]
```

То есть 4-байтовый **big-endian** префикс длины несжатых данных, за которым —
обычный zlib-поток (идентично формату функций `qCompress`/`zlib`).
Рекомендация писателям: применять сжатие, только если оно реально уменьшает
данные (для JPEG/PNG это почти никогда не так).

### 5.2 CRC-32

`crc32` вычисляется по **несжатым** байтам. Алгоритм: CRC-32/ISO-HDLC —
полином `0xEDB88320` (отражённый), начальное и финальное значение
`0xFFFFFFFF` (совпадает с `zlib.crc32`, `gzip`, PNG).

Контрольное значение: `crc32(b"123456789") == 0xCBF43926`.

Значение `0` в поле crc32 означает «контрольная сумма не проверялась»;
писатели должны всегда записывать реальное значение.

## 6. Рекомендации и правила

1. **Имена записей** — исходные имена файлов. Дубликаты допустимы (контейнер
   не требует уникальности). Имя может содержать `/` — рекомендуется
   использовать его как относительный путь внутри альбома.
2. **Читатели** должны отвергать файл, если magic не совпал или `version`
   больше поддерживаемой.
3. **Смещения** должны удовлетворять `offset + storedSize ≤ размер файла`.
   Нарушение = повреждённый файл.
4. Пустой альбом (count = 0, файл из одного заголовка) — валиден.
5. Ошибки CRC/распаковки отдельной записи не обязаны ломать весь альбом:
   читатель может пропустить повреждённую запись и продолжить.

## 7. Версионирование

Поле `version` описывает структуру заголовка и индекса. Формат версии 1
заморожен: будущие версии могут только добавлять поля в конец записей
индекса или новые флаги, не меняя смещения существующих полей. При неизвестной
версии читатель обязан отказаться от чтения.

## 8. Минимальный пример чтения на Python

```python
import struct, zlib

MAGIC = b"QTIVP1\x00\x00"

def read_album(path):
    data = open(path, "rb").read()
    assert data[:8] == MAGIC, "not a .qtivp album"
    version, flags, count = struct.unpack_from("<HHI", data, 8)
    assert version == 1

    off, entries = 16, []
    for _ in range(count):
        (nlen,) = struct.unpack_from("<H", data, off); off += 2
        name = data[off:off + nlen].decode("utf-8");    off += nlen
        (mlen,) = struct.unpack_from("<H", data, off); off += 2
        mime = data[off:off + mlen].decode("ascii");    off += mlen
        w, h, raw, stored, eoff, eflags, crc = struct.unpack_from("<IIIIQII", data, off)
        off += 32
        blob = data[eoff:eoff + stored]
        if eflags & 1:                      # zlib
            assert struct.unpack_from(">I", blob, 0)[0] == raw
            blob = zlib.decompress(blob[4:])
        assert len(blob) == raw
        assert zlib.crc32(blob) & 0xFFFFFFFF == crc
        entries.append((name, mime, w, h, blob))
    return entries
```
